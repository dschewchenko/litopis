Working examples

Date picker guides

Copy complete patterns for single dates, bounded booking windows, localized input, popovers and programmatic control. Every example below runs the current DOM API.

Single date

Mount a picker on any element. The controller returns the current form value in YYYY-MM-DD format.

ts 
import { getToday } from "@litopis/core";
import { createDatePicker } from "@litopis/dom";

const picker = createDatePicker(root, {
  label: "Appointment date",
  today: getToday(),
});

picker.getValue();

Min and max

Calendar cells outside the allowed range are disabled by the shared state layer, so adapters do not implement the rule again.

ts 
import { addDays, getToday } from "@litopis/core";

const today = getToday();

createDatePicker(root, {
  label: "Booking date",
  min: addDays(today, -15),
  max: addDays(today, 15),
});

Date format and week start

Display format is explicit. Week start follows locale by default and can be overridden.

ts 
createDatePicker(root, {
  firstDayOfWeek: 6,
  inputFormat: "mm/dd/yyyy",
  label: "Weekend trip",
});

Localization

locale is a BCP 47 tag used for month names, weekday labels and ARIA text through native Intl. Unsupported or invalid locales fall back to en-US. Week start uses native locale data when available, with compact region data only for browsers that do not expose it. Calendar math is proleptic Gregorian, so historical Julian/Gregorian cutovers are not modeled.

ts 
createDatePicker(root, {
  inputFormat: "dd.mm.yyyy",
  label: "Date",
  locale: "uk-UA",
});

createDatePicker(root, {
  firstDayOfWeek: 1,
  locale: "en-US",
});

Input popover

Use popover mode when the calendar should open over the page. It uses the browser popover top layer and CSS anchor positioning.

ts 
createDatePicker(root, {
  calendarMode: "popover",
  inputFormat: "dd.mm.yyyy",
  showOutsideDays: false,
  showSeason: true,
  targetSize: "comfortable",
});

Programmatic state

Controllers can update value, visible month and options without remounting the calendar. setOptions replaces the option object while preserving the current selected value unless a new selected value is supplied.

ts 
import { addDays, addMonths, getToday, startOfMonth } from "@litopis/core";

const today = getToday();
const picker = createDatePicker(root, { today });

picker.setDate(addDays(today, 9));
picker.setVisibleMonth(startOfMonth(addMonths(today, 6)));
picker.goToToday();
picker.setOptions({ showSeason: true, showOutsideDays: false });

Typed values

Litopis uses plain date values internally and converts at the boundary. That avoids local time shifts while still leaving room for JavaScript Date integration.

Internal value { day, month, year }, years 0001 to 9999
Form value YYYY-MM-DD
Input masks yyyy-mm-dd, dd.mm.yyyy, mm/dd/yyyy
Adapter value DateValue; adapters can convert at the app boundary
